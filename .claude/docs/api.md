# API

Базовый адрес: `http://localhost:3001` (порт задаётся `API_PORT`). Swagger UI: `/docs`. CORS включён. Формат — JSON.

Контракты запросов и ответов определены в `packages/shared/src/index.ts`; ниже они пересказаны для удобства.

## Сводка

| Метод    | Путь                 | Auth | Успех | Описание                                |
| -------- | -------------------- | ---- | ----- | --------------------------------------- |
| `POST`   | `/auth/register`     | —    | 201   | Регистрация, возвращает токен           |
| `POST`   | `/auth/login`        | —    | 200   | Вход, возвращает токен                  |
| `GET`    | `/auth/me`           | JWT  | 200   | Текущий пользователь                    |
| `GET`    | `/categories`        | JWT  | 200   | Список категорий пользователя           |
| `POST`   | `/categories`        | JWT  | 201   | Создать категорию                       |
| `PATCH`  | `/categories/:id`    | JWT  | 200   | Частично изменить категорию             |
| `DELETE` | `/categories/:id`    | JWT  | 204   | Удалить категорию                       |
| `POST`   | `/transactions`      | JWT  | 201   | Создать транзакцию                      |
| `GET`    | `/transactions`      | JWT  | 200   | Страница транзакций + итоги за период   |
| `GET`    | `/transactions/:id`  | JWT  | 200   | Одна транзакция                         |
| `PATCH`  | `/transactions/:id`  | JWT  | 200   | Частично изменить транзакцию            |
| `DELETE` | `/transactions/:id`  | JWT  | 204   | Удалить транзакцию                      |

## Общие правила

**Авторизация.** Защищённые эндпоинты требуют заголовок `Authorization: Bearer <accessToken>`. Нет заголовка, неверная схема, невалидный или просроченный токен — `401`. Время жизни токена — `JWT_EXPIRES_IN` (по умолчанию `1h`).

**Валидация.** Тело и query проверяются Zod-схемами. Ошибка — `400` с телом `error.flatten()` (`{ formErrors, fieldErrors }`).

**Изоляция.** Каждый пользователь работает только со своими данными. Чужая и несуществующая сущность неразличимы — оба случая дают `404`.

**Типы значений.** `amount` в ответах — `number`; даты — ISO 8601 строки (UTC).

**Коды ошибок.**

| Код | Когда                                                                  |
| --- | ---------------------------------------------------------------------- |
| 400 | Тело/query не прошли валидацию                                         |
| 401 | Нет/невалиден JWT; неверный email или пароль при логине                |
| 404 | Сущность не найдена или принадлежит другому пользователю               |
| 409 | Дубликат (email, имя категории) или удаление используемой категории    |

## Auth

### `POST /auth/register`

Тело (`registerSchema`):

| Поле       | Тип    | Правила           |
| ---------- | ------ | ----------------- |
| `name`     | string | не пустое         |
| `email`    | string | валидный email    |
| `password` | string | минимум 8 символов |

Ответ `201` (`AuthResponse`):

```json
{
  "accessToken": "<jwt>",
  "user": { "id": "cl...", "name": "Иван", "email": "ivan@example.com" }
}
```

Ошибки: `400`; `409` — email уже зарегистрирован (email нормализуется в нижний регистр).

### `POST /auth/login`

Тело (`loginSchema`): `email` (валидный email), `password` (не пустой). Ответ `200` — `AuthResponse`, как у регистрации.

Ошибки: `400`; `401` — неверные учётные данные (одинаковый ответ для неизвестного email и неверного пароля).

### `GET /auth/me`

Ответ `200`: `{ "id", "name", "email" }`. Ошибки: `401` — нет токена или пользователь удалён.

## Categories

Все эндпоинты — под JWT; видны только категории текущего пользователя.

Объект категории (`CategoryResponse`): `id`, `name`, `color` (`string | null`), `icon` (`string | null`), `createdAt`.

> Сервис возвращает запись Prisma как есть, поэтому в ответе также присутствует `userId`.

### `GET /categories`

Ответ `200` — массив категорий, отсортирован по `name` по возрастанию.

### `POST /categories`

Тело (`createCategorySchema`):

| Поле    | Тип    | Правила                              | Обязательно |
| ------- | ------ | ------------------------------------ | ----------- |
| `name`  | string | trim, 1–50 символов                  | да          |
| `color` | string | HEX вида `#RRGGBB`                   | нет         |
| `icon`  | string | до 50 символов                       | нет         |

Ответ `201` — созданная категория. Ошибки: `400`; `409` — категория с таким именем у пользователя уже есть.

### `PATCH /categories/:id`

Тело (`updateCategorySchema`): те же поля, все опциональны, но нужно передать хотя бы одно. Ответ `200` — обновлённая категория. Ошибки: `400`; `404`; `409` — дубликат имени.

### `DELETE /categories/:id`

Ответ `204` без тела. Ошибки: `404`; `409` — категория используется в транзакциях (сначала нужно удалить или перенести транзакции).

## Transactions

Все эндпоинты — под JWT; у каждого пользователя свои транзакции.

Объект транзакции (`TransactionResponse`):

```json
{
  "id": "cl...",
  "amount": 1250.5,
  "type": "expense",
  "description": "Продукты",
  "date": "2026-11-10T12:00:00.000Z",
  "categoryId": "cl...",
  "createdAt": "2026-11-10T12:01:02.000Z"
}
```

### `POST /transactions`

Тело (`createTransactionSchema`):

| Поле          | Тип    | Правила                                                    | Обязательно |
| ------------- | ------ | ---------------------------------------------------------- | ----------- |
| `amount`      | number | > 0, до 2 знаков после запятой, ≤ 9 999 999 999.99          | да          |
| `type`        | enum   | `income` \| `expense`                                      | да          |
| `description` | string | trim, до 255 символов                                      | нет         |
| `date`        | string | ISO 8601 datetime (например `2026-11-10T12:00:00Z`)        | да          |
| `categoryId`  | string | не пустой; категория должна принадлежать пользователю      | да          |

Ответ `201` — транзакция. Ошибки: `400`; `404` — категория не найдена или чужая.

### `GET /transactions`

Query-параметры (`listTransactionsQuerySchema`, строки приводятся к числам):

| Параметр | Тип | Правила                                 | По умолчанию                  |
| -------- | --- | --------------------------------------- | ----------------------------- |
| `year`   | int | 1970–9999                               | без `year` — за всё время     |
| `month`  | int | 1–12, **только вместе с `year`**        | весь год                      |
| `page`   | int | 1–100000                                | 1                             |
| `limit`  | int | 1–100                                   | 10                            |

Период — UTC, полуинтервал `[from, to)`: месяц целиком либо весь год. Порядок записей: `date desc, createdAt desc, id desc`.

Ответ `200` (`TransactionsListResponse`):

```json
{
  "items": [ /* TransactionResponse, только текущая страница */ ],
  "summary":    { "income": 5000, "expense": 1250.5, "balance": 3749.5 },
  "pagination": { "page": 1, "limit": 10, "total": 42 }
}
```

`summary` считается по **всему** периоду, а не по странице; `total` — число записей в периоде. Запрос без параметров отдаёт только первые 10 записей.

Ошибки: `400` — невалидные параметры (в том числе `month` без `year`).

### `GET /transactions/:id`

Ответ `200` — транзакция. Ошибки: `404`.

### `PATCH /transactions/:id`

Тело (`updateTransactionSchema`): поля как у создания, все опциональны, нужно передать хотя бы одно. Если меняется `categoryId`, новая категория проверяется на владение. Ответ `200` — обновлённая транзакция. Ошибки: `400` (пустое тело или невалидные поля); `404` — транзакция или новая категория не найдена/чужая.

### `DELETE /transactions/:id`

Ответ `204` без тела. Ошибки: `404`.
