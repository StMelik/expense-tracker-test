# База данных

PostgreSQL 16 (Docker Compose, сервис `postgres`), ORM — Prisma 6. Схема: `apps/api/prisma/schema.prisma`, миграции: `apps/api/prisma/migrations/`. Подключение — `DATABASE_URL` из корневого `.env`.

## Связи

```
User 1 ──── N Category 1 ──── N Transaction N ──── 1 User
 │                                                   ▲
 └───────────────────────────────────────────────────┘
```

- `User` 1—N `Category` (`onDelete: Cascade` — при удалении пользователя удаляются его категории);
- `User` 1—N `Transaction` (`onDelete: Cascade`);
- `Category` 1—N `Transaction` (без каскада: удалить категорию с транзакциями нельзя — это дополнительно проверяет сервис и отдаёт `409`).

Все идентификаторы — строки `cuid()`.

## Таблицы

### `User` — пользователь

| Поле           | Тип        | Ограничения            | Назначение                                                    |
| -------------- | ---------- | ---------------------- | ------------------------------------------------------------- |
| `id`           | String     | PK, `cuid()`           | Идентификатор; попадает в JWT как `sub`                       |
| `name`         | String     |                        | Отображаемое имя (показывается в шапке)                       |
| `email`        | String     | **unique**             | Логин. Хранится в нижнем регистре                             |
| `passwordHash` | String     |                        | bcrypt-хэш пароля (10 раундов); сам пароль не хранится        |
| `createdAt`    | DateTime   | `now()`                | Дата регистрации                                              |
| `updatedAt`    | DateTime   | `@updatedAt`           | Обновляется Prisma при каждом изменении                       |

`passwordHash` никогда не возвращается в API: handler'ы отдают `PublicUser` (`id`, `name`, `email`), хэш — только внутреннему запросу логина.

### `Category` — категория транзакций

| Поле        | Тип      | Ограничения                       | Назначение                                              |
| ----------- | -------- | --------------------------------- | ------------------------------------------------------- |
| `id`        | String   | PK, `cuid()`                      | Идентификатор                                           |
| `name`      | String   | уникальна пара `(userId, name)`   | Название («Еда», «Зарплата»), 1–50 символов             |
| `color`     | String?  |                                   | HEX-цвет `#RRGGBB` для оформления в UI                  |
| `icon`      | String?  |                                   | Имя иконки (до 50 символов)                             |
| `userId`    | String   | FK → `User.id`, cascade           | Владелец — категории личные                             |
| `createdAt` | DateTime | `now()`                           | Дата создания                                           |

Индексы: unique `(userId, name)` — у одного пользователя не может быть двух категорий с одним именем (у разных — может); `index(userId)` — выборка категорий пользователя.

### `Transaction` — доход или расход

| Поле          | Тип             | Ограничения             | Назначение                                                       |
| ------------- | --------------- | ----------------------- | ---------------------------------------------------------------- |
| `id`          | String          | PK, `cuid()`            | Идентификатор                                                    |
| `amount`      | Decimal(12,2)   |                         | Сумма, всегда положительная; знак определяет `type`              |
| `type`        | TransactionType |                         | `income` (доход) или `expense` (расход)                          |
| `description` | String?         |                         | Произвольный комментарий (до 255 символов)                       |
| `date`        | DateTime        |                         | Дата самой операции (задаёт пользователь), по ней идут периоды   |
| `categoryId`  | String          | FK → `Category.id`      | Категория операции                                               |
| `userId`      | String          | FK → `User.id`, cascade | Владелец                                                         |
| `createdAt`   | DateTime        | `now()`                 | Когда запись создана (не путать с `date`)                        |
| `updatedAt`   | DateTime        | `@updatedAt`            | Когда запись последний раз менялась                              |

Индексы: `index(userId, date)` — основной запрос (транзакции пользователя за период с сортировкой по дате); `index(categoryId)` — подсчёт транзакций категории при её удалении.

`date` — время операции, `createdAt` — время вставки; в списке сортировка `date desc, createdAt desc, id desc` (`id` — тай-брейк для стабильной пагинации).

### Enum `TransactionType`

`income` | `expense`.

## Миграции

| Миграция                                   | Что делает                                              |
| ------------------------------------------ | ------------------------------------------------------- |
| `20261109120413_init`                       | `Category`, `Expense` (первая версия)                   |
| `20261109122101_add_user`                   | `User`                                                  |
| `20261109130000_add_category_user`          | `Category.userId`, связь с `User`, unique `(userId, name)` |
| `20261109140000_add_transactions`           | `Expense` заменена на `Transaction`, enum `TransactionType` |

Новая миграция и изменение `schema.prisma` коммитятся вместе. Как создавать — в [dev-guide.md](dev-guide.md#как-добавить-миграцию).

## Заметки

- Деньги хранятся как `Decimal(12,2)` (точность без ошибок float); в API превращаются в `number`.
- Суммы за период считает БД (`groupBy` по `type` с `_sum.amount`), баланс = `income − expense`.
- Границы периодов (`year`/`month`) вычисляются в UTC.
