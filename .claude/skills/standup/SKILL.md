# Стендап-отчёт

Задача: собрать коммиты за вчерашний день и подробно описать, что было сделано.

## Шаги

1. Определи дату: `date -d yesterday +%F` (вчера) и `date +%A` (день недели). Если сегодня понедельник — «вчера» считай последним рабочим днём (пятница, `date -d "last friday" +%F`) и сообщи об этом в отчёте.
2. Определи автора: `git config user.name`. Показывай только его коммиты.
3. Получи коммиты по всем веткам за нужный день:
   `git log --all --no-merges --author="<имя>" --since="<дата> 00:00" --until="<дата> 23:59:59" --date=format:%H:%M --pretty=format:"%h %ad %s%n%b" --stat`
4. Для неочевидных коммитов изучи изменения (`git show <hash> --stat` / `git show <hash>`), чтобы понять суть, а не пересказывать заголовок.
5. Если коммитов нет — так и скажи, предложи проверить другую дату; ничего не выдумывай.

## Формат вывода (на русском)

```
## Стендап за <дата>

### Что сделано
- **<область: api / web / shared / docs / chore>** — <что именно сделано и зачем, 1–2 предложения>
  - <детали: ключевые файлы, эндпоинты, компоненты, миграции>

### Ветки и коммиты
- `<ветка>`: `<hash>` <заголовок коммита>

### Итог
<1–2 предложения: общий результат дня>
```

## Правила

- Группируй коммиты по смыслу/фиче, а не по хронологии; связанные коммиты объединяй в один пункт.
- Описывай результат для человека («добавлен CRUD категорий»), а не технический список файлов.
- Упоминай эндпоинты, миграции Prisma, изменения в `packages/shared`, если они были.
- Не добавляй блоки «Планы на сегодня» и «Блокеры» — в git этого нет; предложи пользователю дополнить их самому.
- Ничего не коммить, не пуш и не меняй: скилл только читает историю.
